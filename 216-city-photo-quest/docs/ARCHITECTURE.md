# Архитектура 216 · city-photo-quest

## Схема

```
index.html → src/main.tsx → App (#edit | #play)
   ├─ ui/Editor.tsx     ── core/quest-editor.ts   формат пакета, правки, проверка готовности, разбор файла
   │                     ── core/image.ts          фото → JPEG ≤1280 px (canvas)
   │                     ── core/quest-export.ts   самостоятельный HTML
   ├─ ui/Player.tsx     ── core/player-progress.ts прогресс: открытое задание, попытки, подсказки
   │                     ── core/answer-checker.ts нормализация и сравнение
   └─ ui/useQuestDraft  ── core/store.ts           IndexedDB «city-photo-quest» (+ текстовая копия в localStorage на pagehide)
```

Сервера нет. Сборка Vite с `base: './'` открывается из корня сайта и из вложенного пути GitHub Pages.

## Формат пакета

```ts
Quest = { format: 'city-photo-quest', version: 1, id, title, intro, updatedAt,
          tasks: [{ id, question, hint, answers: string[], photo: { name, dataUrl, width, height, alt } | null }] }
```

Фото хранятся как `data:image/...` внутри пакета: черновик, пакет `.json` и выгрузка самодостаточны. `parsePackage` проверяет формат, версию, задания (не больше 40), строки ответов, что фото именно `data:image/(jpeg|png|webp|svg+xml)` и не больше ~2,2 МБ, отбрасывает лишние поля.

## Проверка ответа

`normalizeAnswer(s)`: NFC → нижний регистр (`ru-RU`) → ё→е → убрать кавычки «»„“"'` → неразрывные пробелы, табуляции и переводы строк → пробел → разные тире → дефис → схлопнуть пробелы → обрезать пробелы и `.,!?;:` по краям. Одна и та же функция применяется к вводу и к каждому варианту автора. Ответ верен, если нормализованный ввод равен нормализованному варианту. Порядок слов и опечатки не исправляются: «Ёлочная улица» не равно «улица Ёлочная», автор перечисляет варианты сам. В редакторе поле «Проверить, примется ли ответ» показывает результат и нормализованную строку.

## Прогресс

`Progress = { questId, current, attempts[], hints[], startedAt, finishedAt }`, ключ `cpq.progress.<id>`. `submit`: пустой ввод — не попытка; неверный — +1 попытка, задание то же; верный — следующее задание, после последнего — `finishedAt`. При чтении прогресс приводится к текущему составу квеста (`restoreProgress`): чужой `questId` или мусор — начать сначала, `current` ограничен числом заданий.

## Выгрузка

`buildStandaloneHtml(quest)` собирает одну страницу:

- `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; img-src data:; style-src 'unsafe-inline'; script-src 'unsafe-inline'">` — страница физически не может обратиться к сети;
- `<script type="application/json" id="quest-data">` с данными (экранированы `<`, U+2028, U+2029);
- `<script>` с `standalonePlayer` и `normalizeAnswer`, вставленными через `Function.prototype.toString()`. Обе функции самодостаточны, это проверяет юнит-тест и сквозной тест на собранной (минифицированной) версии;
- стили встроены, шрифты системные.

Проигрыватель строит DOM через `createElement` и `textContent` (никакого `innerHTML` с данными), повторяет правила `player-progress.ts` и хранит прогресс под тем же ключом. HTML собирается только по нажатию «Скачать»: при 40 больших фото сборка занимает около 0,7 с, и пересборка на каждую правку тормозила бы ввод.

Имена файлов — транслитом (`kvest-detali-starogo-kvartala.html`): в части окружений кириллица в имени загрузки превращается в «download».

## Черновик

IndexedDB, одна запись `current`. Действия (фото, порядок, удаление, новый квест, демо, открытие пакета) сохраняются сразу, набор текста — через 300 мс паузы. Следующее состояние считается от `latest.current` до `setState`, чтобы сохранение не записало версию до правки. Запись в IndexedDB при закрытии вкладки может не успеть, поэтому на `pagehide` и при скрытии вкладки несохранённый текст (без фото, он маленький) синхронно пишется в localStorage `cpq.v1.unsaved-text` и при следующем открытии накладывается на черновик того же квеста, если он новее. Если IndexedDB недоступна, приложение работает в памяти и предлагает сохранить пакет `.json`.

## Решения и причины

| Решение | Причина |
|---|---|
| Один HTML-файл вместо ссылки на сайт | квест нужен на улице, где интернет нестабилен; файл можно переслать в мессенджере |
| CSP без сети в выгрузке | гарантия офлайн-работы и защита от внедрённого содержимого пакета |
| Проигрыватель выгрузки без React | файл меньше (11 КБ на демо), нет зависимости от сборки |
| Фото уменьшаются до 1280 px JPEG | снимок телефона 3–8 МБ, квест из 10 заданий иначе весил бы 50 МБ |
| Прогресс по id пакета | два разных квеста в одном браузере не смешивают прогресс |
