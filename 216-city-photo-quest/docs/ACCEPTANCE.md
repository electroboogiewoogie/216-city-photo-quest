# Приёмка 216 · city-photo-quest

## Как повторить проверки

```bash
npm ci
npm run typecheck
npm test                 # 10 юнит-тестов (Vitest)
npm run e2e:install      # один раз: Chromium для Playwright
npm run e2e              # 13 сквозных тестов по dist/ (вложенный путь и корень)
npm run build && npm run e2e
```

Замер раунда 4 печатается строкой `PERF216 {...}` в выводе `npx playwright test e2e/perf.spec.ts`.

## Раунд 1. Правила и полнота продукта

Сверка с ТЗ: упорядоченные задания с локальными изображениями; одинаковая нормализация регистра и пробелов для ввода и вариантов; принимаются только варианты автора; экспорт — отдельный HTML с изображениями и проигрывателем; черновик и прогресс локально; на каждом шаге хранится открытое задание и число попыток; после верного ответа открывается следующее, после последнего — завершение; модули `quest-editor`, `answer-checker`, `player-progress`, `quest-export`; прогресс по id пакета.

| Проверка или находка | Результат |
|---|---|
| Русские символы | «ё/е», заглавные кириллицей, «й» в двух формах Юникода (готовая и «и» + знак краткости) совпадают после NFC — юнит-тест |
| Находка: в исходник попал буквальный символ U+2028 внутри регулярного выражения (экранирование JSON в `quest-export.ts`), и сборка падала с «Unterminated regular expression»: для JavaScript это перевод строки | символы заменены на ` `-последовательности во всех файлах, юнит-тест на `safeJson` |
| Самодостаточность встраиваемых функций | `normalizeAnswer` и `standalonePlayer` компилируются из своего текста отдельно (юнит-тест), выгрузка из минифицированной сборки проходит приёмку в другом профиле (e2e) |
| Решение: фото не обязательно | без фото — предупреждение, без вопроса или вариантов ответа — выгрузка недоступна. Задание-загадка без фото тоже бывает полезно |

## Раунд 2. Ошибки, данные и восстановление

## Раунд 3. Удобство и доступность

Просмотр снимков 1280×860 и 360×740: редактор с демо, игра, выгруженный файл с подсказкой.

| Находка | Исправление | Повторная проверка |
|---|---|---|
| Стандартное поле выбора файла для фото было высотой 21 px — меньше порога 40 px для пальца | высота 44 px | `a11y.spec.ts` проверяет и кнопки, и поля файла |
| В длинном квесте выгрузка была только внизу страницы, о готовности сверху ничего не говорилось | сводка сверху: «Заданий: 3 · готов к выгрузке» или «нужно исправить: N» и кнопка «К выгрузке ↓» с переводом фокуса | e2e приёмки |

Игра: фокус на заголовке нового задания, Tab ведёт в поле ответа, Enter проверяет, полоса прогресса с `aria-valuenow`, у фото есть описание (автор задаёт его в редакторе). На 320 px нет горизонтальной прокрутки в редакторе, игре и выгруженном файле. Удаление задания — с подтверждением на месте, без диалоговых окон браузера.

## Раунд 4. Производительность и качество реализации

Худший случай: 40 заданий (предел редактора), фото 1280×960 JPEG с шумом, который почти не сжимается, — 32 МБ. Обычный снимок такого размера после перекодировки весит 150–400 КБ.

| Замер | Время |
|---|---|
| Открыть пакет 32 МБ до 40 карточек | 2,7–3,2 с |
| Ввод 20 символов в вопрос при 40 фото на странице | 208–219 мс (около 10 мс на символ) |
| Выгрузка HTML (сборка и скачивание) | 0,67–0,76 с |
| Открытие выгруженного файла до первого задания | 0,78–0,80 с |
| Демо-квест: размер выгрузки | 11 КБ |

Сборка HTML занимает около 0,7 с при 40 больших фото, поэтому HTML собирается только по нажатию «Скачать». Это решение принято при написании редактора, до замера, замер подтвердил его: пересборка на каждое нажатие клавиши дала бы 0,7 с задержки ввода.

## Известные ограничения

- Опечатки и порядок слов не прощаются: все варианты перечисляет автор.
- Прогресс выгруженного файла — localStorage браузера. Для файлов, открытых с диска (`file://`), часть мобильных браузеров не сохраняет localStorage между запусками.
- Нет GPS, карты и общей таблицы результатов.
- Пакет с фото хранится целиком в IndexedDB этого браузера: очистка данных сайта удаляет черновик, поэтому стоит сохранять пакет `.json`.
