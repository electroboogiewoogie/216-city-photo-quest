# Публикация проекта 216 Городской фотоквест

Имя репозитория — `city-photo-quest`. Профиль — браузерное приложение (статический сайт, GitHub Pages).

## Первый запуск после распаковки

1. Распакуйте ZIP и откройте папку `216-city-photo-quest` в локальном агенте с доступом к файлам и GitHub либо в терминале.
2. Требования к окружению — Node.js 22.12+ и npm 10+ (для готовой сборки достаточно Node.js или Python 3). Команды установки и запуска — `npm ci`, затем `npm run dev` для разработки или `npm run serve:dist` для готовой сборки из `dist/`.
3. Откройте http://localhost:5216/ (разработка) или http://127.0.0.1:4316/ (готовая сборка). Для демо нажмите «Открыть демо-квест из трёх заданий». Ожидаемый результат: три задания с картинками. В режиме «Пройти квест» ответ `1908` даёт «Неверно» и не открывает следующее задание, `1907 ГОД` принимается. «Скачать квест для игры (.html)» сохраняет `kvest-detali-starogo-kvartala.html`, который открывается в другом браузере без интернета.
4. Команды тестов и сборки — `npm run typecheck`, `npm test`, `npm run build`, один раз `npm run e2e:install`, затем `npm run e2e`. Всё сразу — `npm run verify`.

## Проверка аккаунта и публикация

Агент проверяет активную сессию GitHub и логин владельца. При работе через GitHub CLI выполните `gh auth status` и `gh api user --jq .login`. Если требуется вход, используйте браузерный вход `gh auth login --web`. Равнозначный вариант — подключённый GitHub с разрешением на создание репозитория и загрузку файлов. Сначала проверьте, что учётные данные относятся к участнику.

Проверьте список файлов для отправки, текущее состояние Git, remote и отсутствие секретов. Папки `node_modules/`, `dist/`, `test-results/` исключены через `.gitignore`: сайт собирает workflow. Если папка ещё не является Git-репозиторием, создайте его (`git init -b main`) и сделайте первый коммит с корректным описанием и авторством. Не переписывайте историю. Если на GitHub под этим именем уже есть репозиторий, остановитесь перед изменением, объясните, что найдено, и предложите другое имя или согласованный способ обновления. Используйте обычную отправку без принудительной перезаписи.

При новой публикации через CLI используйте `gh repo create OWNER/city-photo-quest --source=. --remote=origin --push --private` или замените `--private` на `--public` по выбору владельца. Перед этим проверьте доступность имени (`gh repo view OWNER/city-photo-quest` должен вернуть «not found») и отсутствие конфликтующего `origin` (`git remote -v`). После отправки проверьте владельца, наличие ветки `main` и файлов и откройте полученную ссылку с нужными правами доступа.

## Развёртывание этой версии

Способ — GitHub Pages через GitHub Actions. Workflow `.github/workflows/pages.yml` при каждом push в `main` выполняет `npm ci`, `npm test`, `npm run build` и публикует `dist/`.

1. В репозитории откройте Settings → Pages → Build and deployment → Source: **GitHub Actions** (через CLI: `gh api -X POST repos/OWNER/city-photo-quest/pages -f build_type=workflow`).
2. Запустите workflow: push в `main` или `gh workflow run "Deploy to GitHub Pages"`. Дождитесь завершения: `gh run watch`.
3. Адрес сайта — `https://OWNER.github.io/city-photo-quest/`. Вложенный путь настраивать не нужно: сборка использует относительные пути (`base: './'` в `vite.config.ts`), это проверяют e2e-тесты проекта `nested-path`.
4. Проверка по рабочей ссылке: главная страница открывается, демо-квест загружается, неверный ответ не открывает следующее задание, «Скачать квест для игры (.html)» сохраняет файл, черновик сохраняется после обновления страницы. Автоматически: `E2E_BASE_URL=https://OWNER.github.io/city-photo-quest/ npx playwright test --project=nested-path`.

GitHub Pages для приватного репозитория доступен не на всех тарифах. Если Pages недоступен, оставьте локальный запуск `npm run serve:dist`.

В результате должны быть ссылка на репозиторий с владельцем и видимостью и один из двух результатов по демо: проверенная ссылка на развёрнутый сайт либо подтверждённый локальный адрес с командой запуска.
